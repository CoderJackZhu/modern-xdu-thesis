> 验收过程、复核实出的问题与修复见 [本科验收报告](本科验收报告.md)。

给实现者（人或编码工具）的任务说明。**目标：给本模板加入本科毕业设计（论文）支持。**
规格与要求见 [本科规格](本科规格.md)（具体数值的唯一出处）与 [本科模块调研](本科模块调研.md)（背景与可行性）。

本文件是自包含的任务书 —— 不需要额外上下文即可开工；但**动手前必须通读
[本科规格](本科规格.md)**，所有数值以它为准，不要凭记忆或「常见做法」填写。

## 一、当前状态

`modern-xdu-thesis` 是一个 Typst 包，目前只覆盖**硕士**学位论文（学术学位 / 专业学位 + 盲审模式）。
已完成并发布：版式与官方模板逐项对照通过，用一份 112 页真实论文压测通过，
已提交 Typst Universe（`typst/packages` 的 PR #5818，审核中）。

- 仓库：<https://github.com/CoderJackZhu/modern-xdu-thesis>
- 包入口：`lib.typ`；页面组件在 `pages/`，版式核心在 `layouts/`，工具在 `utils/`
- 示例与交付模板：`template/`（`typst init` 复制的目录）
- 验证：`bash dev/check-all.sh`（当前 13/13 通过）

## 二、要做的事

新增**本科**支持。关键判断已经做出，不要推翻：

1. **本科与硕士不共用文件入口**（版式差异大：版心、行距机制、页码位置、页眉线型都不同）。
2. **并入同一个包**（不另开新包）。
3. **`typst.toml` 的 `[template]` 保留给硕士**（即 `typst init` 默认给硕士），
   本科入口放在包内另处、在文档中说明用法。
4. 具体版式数值：**全部见 [本科规格](本科规格.md)**，含来源标注（官方手册原文 / 官方 LaTeX 类 / 实测）。

概括地说，本科与硕士的差异是：

| 项 | 本科 | 硕士（现状，勿动） |
|---|---|---|
| 版心 | 150 × 247 mm | 155 × 240.93 mm |
| 行距 | **1.5 倍** | 固定 20 磅 |
| 装订线 / 页脚 | 1 cm / 1 cm | 0.5 cm / 1.75 cm |
| 页码 | **页眉行最外侧**（宋体小五） | 页面底端中部 |
| 页眉 | 左页=论文题目 / 右页=章次+章标题；**单线 0.75 磅** | 奇=章名 / 偶=校名；双横线 0.5 磅 |
| 参考文献 | GB/T 7714-2015 | GB/T 7714-2015（已统一） |

需要新做的部分（详见本科规格 §十）：

1. 本科的封面（按实测版式，**并做成可开关**的组件）
2. 页面几何：150 × 247mm、装订线 1cm、页脚 1cm
3. 行距机制改为 **1.5 倍**（与硕士的固定 20 磅是两套算法）
4. 页码移到**页眉行最外侧**，页脚留空
5. 页眉：左页题目 / 右页章次+章标题，底划线**单线 0.75 磅**
6. 附录编号（附录 A；图表式与正文分开：图 A1、表 B2、式(C-3)）
7. 本科的验收期望值表（对照官方 Word 样例与实物论文）

## 三、明确不做

- **不碰硕士部分**的版式与已验证的代码路径（改坏了会连带影响已发布版本）
- **不做装订顺序里的独立表单**（诚信书、任务书、中期检查表、成绩评定表、查重报告等 —— 用户已裁定不做）
- **不改元数据**：包名、版本、作者、许可由用户决定，需要改动先问
- **不引入不必要的依赖**（加 `@preview/...` 包前先确认标准库做不到）
- **不移植 `Hubert9982/typst_xdutemplate` 的代码** —— 该项目**无许可证**（保留所有权利），
  只能看设计思路。本科版式必须对着官方规范自己实现。

## 四、必须遵守的工作方式

本仓库的历史经验：**编译通过 ≠ 输出正确**。迄今出现的每一个 bug 都是「编译零错误、无警告、
输出是错的」——首行缩进全局失效、正文首页页码错、公式无法引用、索引编号丢章前缀、
填空横线画成点线、空白填充页缺页眉页码。

因此：

1. **改完必须跑 `bash dev/check-all.sh`**（编译全部入口 + 各部分验收 + 压测 + 分发验收），
   且必须保持硕士部分的 13/13 全绿。
2. **版式改动必须用 PDF 反向测量**（`dev/verify-*.py` 的写法），不接受「看起来差不多」。
3. **新增验收项必须做负向测试**：把它本该抓到的错误造回去，确认脚本会报红 —— 否则容易
   写出永远通过的「假绿」。
4. **验收脚本必须先拿官方输出自检**（期望值正确时官方自身位移应为 0.00）。
5. 中文注释与文档，与现有风格一致。
6. 详细规约见仓库根目录的 `AGENTS.md`。

## 五、验收标准

本科部分完成的判据：

1. 能编译出符合 [本科规格](本科规格.md) 全部硬约束的 PDF。
2. 对照**官方 Word 样例**（见下节材料）逐项核对通过。
3. 用**实物论文**（本人本科毕业论文，55 页，见下节）压测：总页数、章起始页、
   参考文献条数与源文件一致；流程参照 `docs/压力测试报告.md`（硕士当时怎么做的）。
4. `bash dev/check-all.sh` 全绿（含硕士部分的 13 项）。
5. 新建的验收脚本（本科期望值）有对应的负向测试记录。
6. `typst init` 产物仍自包含、可编译（硕士入口；本科入口亦需实测可用）。

## 七、本机材料位置

若在本机工作，官方材料已备好：

```
~/.hermes/assets/xdu-thesis-official/undergrad/
  jwc-handbook-2019.pdf          本科官方手册（格式真值）
  official-word-template.doc     官方 Word 样例
~/.hermes/assets/xdu-thesis-official/
  xduts.dtx                      含 xduugthesis.cls 的定义（本科官方实现）
```

本科类的提取方式：`xduts.dtx` 用 docstrip 带 `class,thesis,xduugthesis` 选项即可生成
`xduugthesis.cls`；亦可直接从上述 GitHub 仓库取现成的 `.cls`。

对照验收的路径配置写在 `dev/local-paths.sh`（已 gitignore，模板见
`dev/local-paths.example.sh`），或直接用环境变量 `OFFICIAL_PDF` / `STRESS_SRC` 覆盖。
本科部分建议照同一模式增加变量，不要写死路径。

## 八、开工顺序建议

1. 通读 [本科规格](本科规格.md)，把其中每一项数值与来源核对一遍；有疑问先问，不要猜。
2. 把本科的验收期望值表建起来（先有尺子，再动手）—— 从官方 Word 样例与实物论文实测提取。
3. 实现页面几何与行距机制（这是最核心、最容易被别的地方影响的部分）。
4. 做页眉页脚（页码位置、页眉内容与线型）。
5. 做封面（可开关）与附录编号。
6. 用实物论文压测，跑 `dev/check-all.sh`，补负向测试。
7. 文档同步：`README.md`、`写作要求.md` 增加本科用法；`docs/` 相应补充。
