## 2. 关键技术点 1：固定值 20 磅行距的实现

### 2.1 问题

Typst 的 `par(leading)` 是**行盒之间的空隙**，不是基线距。直接 `leading: 20pt` 得到的基线距 = 行盒高度 + 20pt，必然偏大。

### 2.2 机制

把行盒拆成两段：

```
行盒顶  ──────────────  ← top-edge: Δ
      （字身框）
        ──────────────  ← bottom-edge: "baseline"
行间空隙       ← par(leading) = 20pt − Δ
下一行基线
```

- `Δ + leading = 20pt` ⇒ 相邻基线距精确 20pt
- **行盒顶正好落在正文区顶边**，字身框不越过上边距

Δ 的取值：汉字字身框在 20pt 行盒内居中 ⇒ `Δ = (20 − 12)/2 + 0.88 × 12 = 14.56pt`（字号 12pt）。

### 2.3 实测

```
y= 99.599 甲一甲乙…  ← 首行基线
y= 119.599 乙一甲乙…  Δ=+20.000
y= 139.599 乙一甲乙…  Δ=+20.000
…
y= 199.599 乙二乙二…  Δ=+20.000  ← 跨段落同样是 20.000
```

- **段内行距 = 20.000pt**
- **跨段落行距 = 20.000pt**（需额外设 `par(spacing: 20pt − Δ)`，否则 Typst 默认 `spacing: 1.2em` = 14.4pt 会破坏行网格）
- 行内公式、上标、中英混排**不改变行距**
- 栅格化检查：首行字身框顶 = 30.48mm > 30mm 上边距，**不越界**

> 独立公式为块级元素，占约 3 行高，不参与 20pt 行网格。官方模板同样如此，属正常。

### 2.4 每页行数（需注意）

版心高 247mm = 700.16pt，每行刚好 20pt ⇒ 理论上 35 行。**实测：连续段落 35 行；多段落时 34 行。**

余量只有 `700.16 − 700.00 = 0.16pt`，处于浮点临界，段落边界会因 Typst 计入段落尾距而少排一行。官方 LaTeX 因版心取 24cm，稳定 34 行。

**影响**：页面底部的行数会在 34/35 之间波动，视觉上是"最后一行有时排满有时不排满"。
**建议**：决定 —— (a) 接受波动；(b) 版心改 24cm 稳定 34 行；(c) 微调行距/边距消除临界。

## 3. 与官方 LaTeX 输出的实测对照

### 3.1 一个必须先说清的单位问题

| | 单位定义 | 「20 磅」实际等于 |
|---|---|---|
| Word / 规范 | 1/72 英寸 | **20.000 bp** |
| LaTeX | 1/72.27 英寸 | 19.925 bp |
| Typst | 1/72 英寸（= PDF bp） | **20.000 bp** |

**结论：Typst 的 `pt` 与 Word 的「磅」同义**，直接写 20pt 即等于规范要求。官方 LaTeX 的 19.925bp 反而是它自己的换算结果。所以 格式规格 里所有「磅」值在 Typst 中**直接照抄数值即可**，不需要换算。

### 3.2 对照表

| 项目 | 官方 LaTeX | 本模板 | 差 | 说明 |
|---|---|---|---|---|
| 正文首行基线 | 99.53 bp / 35.11mm | 99.60 bp / 35.14mm | +0.07bp | **完全对齐** |
| 段内行距 | 19.925 bp | 20.000 bp | +0.075bp | §3.1 单位差，本模板符合规范 |
| 版心宽 | 439.37 bp / 155.0mm | 439.37 bp / 155.0mm | 0 | 一致 |
| 页眉文字基线 | 73.18 bp / 25.82mm | 70.68 bp / 24.94mm | −0.88mm | 见 §3.3 |
| 双横线 | 27.65 / 28.00mm | 27.21 / 27.56mm | −0.44mm | 见 §3.3 |
| 页码基线 | 788.84 bp / 278.29mm | 278.06mm | −0.23mm | 可接受 |
| 每页行数 | 34 | 35（临界） | +1 | §2.4 |

### 3.3 页眉差异的来由（不是错误）

> **更正**：本节先前把官方 LaTeX 的正文区顶边推为 27.65mm。后续复核发现那是**页眉横线**的位置，不是正文区顶边。用官方正文首行基线 99.53bp 反推：`99.53 − Δ(14.49) = 85.04bp = 30.00mm`，**官方正文区顶边正是 30mm，与 格式规格 §2.1 的裁定一致**。页眉横线在正文区顶边之上 6.68pt（27.65mm），页眉文字基线在其上 11.86pt。

官方 LaTeX 的页眉相对**正文区顶边**：文字基线 −11.86pt、双线 −6.68 / −5.68pt。本模板：文字基线 −14.56pt、双线 −9.31 / −8.96pt。绝对差 0.88mm（页眉文字）。

这是 **格式规格 §2.1「页眉距页顶 20mm」（Word `pgMar header=1134twips`）与官方 LaTeX 页眉布局的固有差异**，不是实现偏差。逐页对照时按此口径判定。

## 4. 格式规格中发现的错误与待决问题

### 4.1 格式规格 §2.3「左右各超出正文 4 磅」是错的

- 官方 LaTeX 2024.04：`\rule[9pt]{\headwidth}{0.5pt}`，宽度 = `\headwidth` = 正文宽
- 现行 xduts：`\hrule \@height \headrulewidth`，同样 = 正文宽
- Word `styles.xml` styleId=20：`<w:pBdr><w:bottom w:val="double" w:sz="4" w:space="1"/>`，无缩进，边框跨整个正文宽
- **实测本模板横线 = 439.37bp = 155.00mm = 正文宽，无外扩**

**三方一致：横线宽度 = 正文宽。** 已在 格式规格 §2.3 修正。

### 4.2 字体回退链缺内置字体

方案 C 要求「系统字体优先，缺失时回退**内置开源字体**」，但仓库目前**没有内置任何开源中文字体**，只有方正仿宋/楷体（商用授权）和 TNR。

实测风险：字号 16pt 的章标题用 `font: ("Times New Roman", "SimHei")`，本机两者都没有黑体时，Typst 落到了系统兜底字体 **Klee-Medium（一款手写体）**，完全不像是排版错误但结果很荒谬。

**待决**：是否引入思源宋体/思源黑体（每个字重约 10–20MB，仓库体积会上一个量级）。当前 `dev/probe-header-footer.typ` 用的是完整回退链（含 `Heiti SC` 等 macOS 字体），本机工作正常。

### 4.3 段前间距在页顶被 Typst 折叠

Word/官方 LaTeX 中，章标题的「段前 24 磅」在**章节首页页顶照常生效**（官方 p23：章标题基线在 44.25mm 处）。Typst 的 `block(above:)` 在页顶会被折叠。

**影响**：章首页的标题位置会比官方高约 24pt（8.5mm）。实现章标题时需显式处理。

### 4.4 拉丁文字字面外伸约 0.6mm

正文含纯拉丁段落时，墨迹右边界实测 185.59mm，超出正文宽 0.59mm。纯中文段落无此现象（184.74mm）。属字体字面外伸，非布局错误。官方输出因正文以中文为主未出现。

### 4.5 目录页码为空（测试写法所致）

`dev/probe-structure.typ` 中目录条目未显示页码，原因是测试里在目录之前把 `counter(page)` 重置了，导致页码引用失效。真实模板中目录在前置部分、正文在后，不会出现。实现目录时正常处理即可。

## 5. 后续页面规格的输入

### 5.1 已可直接复用的代码

`dev/probe-header-footer.typ` 已经是页面核心的可用实现，可直接搬进 `layouts/doc.typ`：

```typst
#let 基线偏移(行盒, 字号) = (行盒 - 字号) / 2 + 0.88 * 字号
#let 上伸 = 基线偏移(20pt, 12pt)   // 14.56pt
#let 行隙 = 20pt - 上伸        // 5.44pt
#set text(top-edge: 上伸, bottom-edge: "baseline")
#set par(leading: 行隙, spacing: 行隙)

#set page(
 margin: (top: 30mm, bottom: 20mm, inside: 30mm, outside: 25mm),
 header-ascent: 30mm - 20mm,  // 页眉帧顶落到 20mm
 footer-descent: 0mm,     // 页脚帧顶落到版心下边界
)
```

### 5.2 两条 Typst 定位规律（实测得出，非文档所述）

- **页眉帧顶 = 上边距 − `header-ascent`**（斜率严格 −1，与文档字号无关）
- **页脚帧顶 = 版心下边界 + `footer-descent`**

前提：页眉/页脚内容必须是**零高度框**且用 `place` 摆放，否则基准会漂移。

### 5.3 测量工具

`dev/measure.py`：编译 `.typ` 并输出每页每个 span 的基线 y、字号、字体。–每阶段验收都用它。

```bash
python3 dev/measure.py dev/probe-header-footer.typ [--pages N]
```

配套（未入库，随时可重写）：栅格化墨迹包围盒检查、PDF 图形（横线）位置提取、官方 `templet.pdf` 逐项测量。见 格式规格 §5.1。

## 6. 补充验证与遗留问题

### 7.1 每页行数 —— 建议：**保持 247mm 版心不动**

§2.4 的结论需要更完整。补充实测（`spacing`/缩进/分隔方式均不影响）：

| 内容形态 | 每页行数 | 末行距版心底部剩余 |
|---|---|---|
| 单行段落流 | **33** | 45.6pt |
| 双行段落流 | **35** | 5.6pt |
| 四行段落流 | 34 / 35 | 5.6–25.6pt |

关键：**所有情形下基线间距都是精确的 20.000pt**（32 个间距无一例外）。行距完全达标，波动只发生在 Typst 的分页判定上。

**官方 `templet.pdf` 自身每页 26–34 行浮动**（受章标题、图表、段落结构影响）。所以「每页固定行数」不是官方要求，波动本身不是缺陷。

版心对比实测：

| 版心 | 单行段落 | 双行段落 |
|---|---|---|
| **247mm（格式规格 裁定，跟规范）** | 33 | **35（排满）** |
| 240mm（官方 LaTeX 现值） | 33 | 33 / 34 波动 |

**结论：保持 247mm。** 它是规范算术（297−30−20），实际表现反而比 24cm 好——双行段落能稳定排满 35 行；改成 24cm 只是把波动区间挪到 33–34，还偏离了 Word。

验收口径改为：**正文满页 34–35 行**；极短的单行段落流可能落 33 行，属 Typst 分页行为，非配置错误。

附带记录一条实现限制：**Typst 的 `bottom-edge` 不接受长度参数**（实测被忽略，只有 `top-edge` 生效）。因此无法把行盒直接做成正好 20pt，只能靠「`top-edge` 长度 + `par(leading)` 补偿」这一组合，`par(spacing)` 也必须同步设置。

### 7.2 字体 —— 建议：**不内置字体文件**

实测官方 `templet.pdf` 全 44 页嵌入的字体**只有**：

| 字体 | 出现次数 | 用途 |
|---|---|---|
| `SimSun`（宋体） | 75 | 正文 |
| `NimbusRomNo9L-Regu/-Medi` | 63 / 14 | 西文（Times New Roman 的开源等价物） |
| `SimHei`（黑体） | 17 | 一级标题 |
| `CMMI/CMSY/CMR/CMEX` | 9 | LaTeX 数学字体 |

**楷体、仿宋一次都没出现**；Word 侧 `styles.xml` 与 `document.xml` 中「楷体」「仿宋」出现 **0 次**。

→ **硕士学位论文只需要三种字体：宋体 / 黑体 / Times New Roman。**

仓库 `fonts/` 现状（实测族名）：

| 文件 | 真实名称 | 授权 |
|---|---|---|
| `Arial/Arial.otf` | `Arial Regular` | Monotype 商业字体，不可再分发 |
| `TimesNewRoman/*.ttf` ×4 | `Times New Roman` | Monotype 商业字体，不可再分发 |
| `FangZheng/FangZhengFangSongJianTi-1.ttf` | `FZFangSong-Z02S` | 方正商用授权 |
| `FangZheng/FangZhengKaiTiJianTi-1.ttf` | `FZKai-Z03S` | 方正商用授权 |

**建议：不内置任何字体文件。** 三条理由：

1. 官方用的 SimSun/SimHei **不可分发**。内置任何开源替代品（思源宋体等）都会让 PDF 嵌入「不是宋体」的字体名，而学校格式检测会检查字体名，得不偿失。
2. 现有内置的 6 个文件**全部是商业字体**（Monotype ×5、方正 ×2），放进 MIT 仓库有版权风险。
3. 楷体/仿宋**用不到**，方正那两个文件是纯负担；Arial 也用不到（官方输出里没有 Arial）。

改为：**系统字体优先 + 完整回退链 + README 写明字体要求**。

- macOS：`Songti SC` / `Heiti SC` / `Times New Roman`（本机实测可用）
- Windows：`SimSun` / `SimHei` / `Times New Roman` ← 最贴近官方
- Linux / CI：`Noto Serif CJK SC` / `Noto Sans CJK SC`（可提供可选下载说明，不进仓库）

附带修正：黑体的西文字体应从 `Arial` 改为 `Times New Roman`（官方输出无 Arial，且 格式规格 §2.2 本就把一级标题西文定为 TNR）。

> **已执行**：`fonts/` 已移出仓库（商用字体不再随仓库分发），`.gitignore` 已加入 `fonts/`。移出后 `dev/probe-header-footer.typ` 的嵌入字体（`STSongti-SC-*` / `TimesNewRomanPS*`）与全部关键测量（横线 27.207/27.56mm、页眉 24.935mm、页码 278.06mm）**与移出前完全一致**，证明内置字体从未被使用。

### 7.3 章标题段前 —— 建议：**按官方，用强间距，页顶不折叠**

官方 `templet.pdf` 章首页实测：章标题基线 **125.44bp**、正文首行 **163.29bp**。

实现（已验证）：

```typst
#show heading.where(level: 1): it => {
 v(24pt)                  // 强间距：页顶不折叠
 set text(size: 16pt, top-edge: 基线偏移(20pt, 16pt))  // = 16.08pt
 align(center, it.body)
 v(18pt)                  // 段后
}
```

实测结果：章标题 **125.119bp**、正文首行 **163.119bp** → 与官方差 **0.32bp / 0.17bp**（不到 0.1mm）。

同时验证了一个此前不确定的点：**章标题与正文共用同一个 20pt 行盒**（`Δ = (20−16)/2 + 0.88×16 = 16.08pt`）是对的——这正是它和官方对得上的原因。

**建议：章标题的段前/段后用显式 `v()`（强间距）实现，不用 `block(above:)`。** 节/小节可继续用 `block(above:)`：Typst 的间距折叠恰好给出正确值（`max(段落尾距 5.44pt, 标题段前)` = 标题段前），而章标题总在新页起，必须用强间距。

附带更正：§3.3 先前把官方正文区顶边推为 27.65mm，实为页眉横线位置。**官方正文区顶边正是 30mm**，与 格式规格 §2.1 裁定一致。
