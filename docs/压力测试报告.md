# 压力测试报告

> 目的：示例论文只有 33 页占位内容，覆盖不到真实体量。这里拿一份**已通过学校格式检查**
> 的真实硕士论文（112 页、专业学位）用本模板重排，与源 `main.pdf` 逐项对照。

## 1. 方法

| 步骤 | 做法 |
|---|---|
| 源 | `github.com/未公开的硕士论文仓库` —— 6 章、26 图、10 表、**101 个公式**、108 处引用、102 条文献 |
| 正文移植 | `pandoc -f latex -t typst` 打底（章节、公式、图、交叉引用、引用都能转），再做后处理 |
| 后处理 | `dev/stress/port.py`：章标题补「第 N 章」、`\(`→`(`、`@key`→`#cite(<key>)`、`@label`→`#ref(...)`、标签去重、`.bib` 去重 |
| 前置数据 | `dev/stress/front-data.py`：`notation` / `abbreviations` / `bio` 从 LaTeX 的 tabular 与 `\section` 直接抽成元组（pandoc 会把它们转成 `#table`，不是模板要的形状） |
| 入口 | `dev/stress/thesis.typ` |
| 对照 | 与源 `main.pdf` 比页数、章起始页、后置部分页、逐页行数 |

复现：

```bash
bash dev/pkg-stage.sh
python3 dev/stress/port.py <源仓库> dev/stress
python3 dev/stress/front-data.py <源仓库>/chapter dev/stress/front-data.typ
typst compile --root . dev/stress/thesis.typ /tmp/stress.pdf
```

## 3. 发现的问题

### 3.1 已修：公式无法被引用

**症状**：正文写 `由公式(2-1)` 时，Typst 报 `cannot reference equation without numbering`。

**根因**：我们的公式编号是「show 规则里手写的一段文本」，公式本体没有 `numbering`，
所以拿不到编号可供引用。真实论文普遍会引用公式。

**修法**：改用真正的 `numbering`，并在其中用 `context` 读章号：

```typst
#let 公式编号(..n) = context {
 let 章 = 章号.get().first()
 text(font: ("Times New Roman",), "(" + str(章) + "-" + numbering("1", ..n) + ")")
}
set math.equation(numbering: 公式编号)
```

修后实测：编号 `(2-1)` 右对齐在 **版心右界 185.00mm**（与官方一致），`@eq:` 引用可用。

### 3.2 已修：索引里的图表编号丢了章前缀

**症状**：插图索引显示「图 **1**」，应为「图 **1.1**」；表格索引显示「表 1」，应为「表 3.1」。

**根因**：`figure` 元素从未设过 `numbering`，索引里 `numbering(f.numbering, …)` 拿到的是
Typst 的默认**全局序号**。

**修法**：`set figure(numbering: 图表编号)`（与公式同样的上下文读数），
并在每章开头**重置 Typst 自己的 figure 计数器**——它不会自动按章归零，
否则第二章的图会编成「2.27」而不是「2.1」。

### 3.3 已修：索引页码用了物理页号

**症状**：插图索引里第一条图注指向 **32**，源论文是 **8**。

**根因**：用了 `f.location().page()`（物理序号），而不是「页计数器在该位置的值」。
前置部分占 24 页，正文第 1 页的物理序号是 25、印刷页号是 1，两者相差 24。
目录页早就用计数器处理过，索引漏了。

**修法**：`numbering(loc.page-numbering(), counter(page).at(loc).first())`，
并对 `page-numbering()` 返回 `none` 的页做兜底（目录页原有这层处理，照搬）。

### 3.4 已修：图注里的引用会打乱参考文献顺序（附上游调研）

**症状**：本模板参考文献 `[1]` 是 `RADFORD A`，源论文 `[1]` 是 `ELGAMMAL A` —— 整份顺序错乱。

**根因**：Typst 的数值型参考文献**按引用首次出现的位置**编号，而插图索引在正文之前（p13 < p25）。
图注里的 `#cite` 在索引页就被渲染了一次，于是那几条文献被排到了最前面。

#### 上游调研结论

| 来源 | 结论 |
|---|---|
| [typst/typst#3994](https://github.com/typst/typst/issues/3994)「Citations in Captions messes with the ordering」 | **与本问题一字不差**。已被关闭为 **duplicate of #1880** |
| [typst/typst#1880](https://github.com/typst/typst/issues/1880)「Footnotes and citations are duplicated in outlines」 | **仍 open，标签含 `bug`** —— 维护者认可这是缺陷，不是有意行为 |
| [#1295 的维护者评论](https://github.com/typst/typst/issues/1295#issuecomment-1853762154) | 给出 workaround：用 `state` 判断「当前是否在渲染大纲」，让索引显示**不含引用的短题注**。即 LaTeX 的 `\caption[短]{长}` |
| 本科模板 `Hubert9982/typst_xdutemplate` | 基于 `modern-nju-thesis`，**根本没有插图索引**（只有目录），所以问题不出现 —— 属于「没这个功能」，不是「解决了」 |

#### 本模板的修法（两层）

**① 自动：索引页渲染条目前 `show cite: it => none`** —— 零用户成本。

一开始判断这招无效（以为元素仍在文档里、仍会被 `bibliography()` 收录），**实测证明是有效的**：
隐藏后引用不参与编号，顺序回归正文。实测压力测试的参考文献顺序与源论文**逐条一致**
（`[1] ELGAMMAL` / `[2] KARRAS` / `[3] JÄHNE` …）。

**② 可选：`索引题注(索引版, 正文版)`** —— 给需要额外精简索引文字的场合，
就是维护者建议的 `state` 方案（LaTeX 的 `\caption[短]{长}`）。

```typst
#figure(image("fig.png"),
 caption: 索引题注([系统框图], [毫米波大规模 MIMO 系统框图 @zhang2023]))
```

实测：插图索引显示「图 2.1 … 系统框图 … 3」，正文图注显示完整版。

#### 回归检查

`dev/verify-body.py` 新增「索引页无引用上标」一项：索引页出现 < 8.5pt 的 `[n]` 即判失败。

## 4. 参考文献标准调研（GB/T 7714-2005 vs 2015）

### 5.1 该用哪一版：官方材料两派，我们的裁定正确

| 来源 | 依据 | 版本 |
|---|---|---|
| 官方《撰写要求》原文 | 「参考文献的著录要符合《文后参考文献著录规则》（GB/T7714-**2005**）要求」 | **2005** |
| 官方 LaTeX `XDUthesis.cls`（2024.04） | `\bibliographystyle{gbt7714-2005}`，且包内自带 `gbt7714-2005.bst` | **2005** |
| 新版类 `xdupgthesis.cls`（参考论文所用） | `\PassOptionsToPackage{style = gb7714-2015}{biblatex}` | 2015 |
| 本科模板 `Hubert9982/typst_xdutemplate` | `style: "gb-7714-2015-numeric"` | 2015 |

**规范原文与官方工具链都指向 2005**，故 格式规格 §6 的裁定（2005）成立。
实践上两版都能过检 —— 参考论文用的 2015，同样通过了学校检查。

**两版的实际渲染差异极小**：同一份 `.bib` 分别用 `gb-7714-2005-numeric` 与
`gb-7714-2015-numeric` 渲染，逐个条目比对，**只有一处不同**：

```
2005: 信息与文献 参考文献著录规则[M]. 北京: 中国标准出版社, 2015.
2015: 信息与文献 参考文献著录规则[Z]. 北京: 中国标准出版社, 2015.
```

（`@standard` 的类型标识从 `[M]` 变为 `[Z]`。）其余 `[J]`/`[D]`/`[M]` 标识、标点、
`等` / `et al.` 处理均一致。Typst 两版样式都内置，切换只需改一处字符串。

### 5.2 查出的真问题：「等」与「et al.」

规范原文：

> 引用文献的作者不超过 3 位时全部列出，超过时列前 3 位，后加「等」字或「et al.」。

即**中文文献用「等」、英文文献用「et al.」**。参考论文的做法正确
（`ELGAMMAL A, LIU B, ELHOSEINY M, et al.`），而**本模板原先把英文条目也输出成「等」**。

**根因**：Typst 的 CSL 渲染只认**文档级**语言（`set text(lang: …)`），
**不支持逐条文献设置**。实测给条目加 `language = {en}` / `language = {en-US}` /
`langid = {english}` 三种写法**全部无效**；把文档语言改成 `en` 则连中文条目也变成 `et al.`。

**上游现状**：CSL 本身无法描述「按文献语言切换渲染方式」；CSL-M 扩展可以，
但 Typst 使用的参考文献引擎（hayagriva）不支持。

**社区解法**（[Typst 中文社区《如何修复英文参考文献中的"等"？》](https://typst-doc-cn.github.io/guide/FAQ/bib-etal-lang.html)）：

| 法 | 做法 | 取舍 |
|---|---|---|
| ① 替换字符 | 对渲染结果做后处理（`modern-nju-thesis` 的 `bilingual-bibliography` 即此法） | 简单快速、不影响性能；本质是查找替换，**可能误判** |
| ② 换参考文献引擎 | 改用 `citext` / `gb7714-bilingual` | 真正按语言自动切换；但**性能从 1s 劣化到 10s+**、`@a @b` 不能直接用、不支持导出 HTML |

本科模板正是用法 ①（其源码里有注释掉的 `bilingual-bibliography` 调用）。

**本模板的实现**：`双语文献()`（`utils/bilingual-bib.typ`）——
与法 ① 同思路的**最小实现，不引入外部依赖**：在 bibliography 的 grid 单元格上做判断，
非中文条目把「等」换成「et al」。

```typst
// 默认开启；需要原样输出时关掉
#references(bib: "/refs.bib", 双语: false)
```

**验证**：压力测试的英文条目与参考论文**逐字一致** ——

```
本模板 [1] ELGAMMAL A, LIU B, ELHOSEINY M, et al. Can: Creative ...
参考论文 [1] ELGAMMAL A, LIU B, ELHOSEINY M, et al. Can: Creative ...
```

参考文献列表整体也一致：**96 条 = 96 条**，顺序与内容逐条对应。

## 5. 顺带发现的规格差异（未改，仅记录）

| 项 | 源论文（新版类） | 本模板 | 说明 |
|---|---|---|---|
| 符号对照表字号 | 10.5pt | 12pt | 与「封面/声明跟哪一代」同源，见 格式规格 §6 第 10 项 |
| 符号对照表列标题 | 符号 / 名称 | 符号 / 符号名称 | 本模板写死了表头，源论文是作者自定义 |
| 表格题注 | — | — | pandoc 转换时丢了 `\caption`，故压力测试里表格无题注（表格样式仍验证到） |

**符号对照表可放数学**：`notation` 的两列接受 content，写 `([$x_0$], [原始输入样本])`
即可渲染成公式；写字符串则按纯文本渲染。此点已补进 README 的接口说明。
